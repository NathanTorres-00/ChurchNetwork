# Marker Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a freehand **Marker** tool (Pen and Highlighter inks) to comment mode. It replaces the box Highlight tool. Many strokes post as one `drawing` mark with an optional note, and each stroke stays on the word or element it marked at any width.

**Architecture:** Pure stroke geometry lives in `review/ink.js` (unit-tested). `review/stroke-anchor.js` ties each stroke to a character in the page's text, or to an element as a fallback. It stores the stroke's points as pixel offsets from that origin plus the font size there, so strokes move and scale with their text. Highlighter strokes along text store a text range that rewraps like a selection. `review/marker.js` turns pointer input into strokes: mouse, one finger with two-finger scroll, and stylus with finger scroll. It draws the stroke live in a fixed overlay. The marks layer draws posted and draft drawings as SVG. The workspace gains the Marker tool, an ink switch, a slim drawing bar below 1280px, the card sketch and the new counts. The backend gains a `drawing` kind with validated strokes.

**Tech Stack:** Plain ES modules in `review/` (no bundler), Convex, Vitest + convex-test + jsdom, Playwright (Chromium).

**Spec:** `docs/superpowers/specs/2026-10-22-marker-design.md`

## Global Constraints

- Plain ES modules in `review/`, no framework, no bundler, no new dependency. Pen outlines are hand-rolled in `ink.js`.
- Nothing new loads or shows outside comment mode. Every new element carries `data-review-ui`.
- Inks are fixed: pen `#D93A22`, highlighter `rgba(255, 205, 40, .5)` with `mix-blend-mode: multiply` and flat caps. Pen width 2.6px and highlighter 16px. At ≤759px viewer width they are 4px and 24px (call 7: about 1.5×).
- Limits, shared through `convex/limits.js`: at most 40 strokes and 6,000 points per drawing, at most 2,000 points per stroke, and coordinates finite with |value| ≤ 20000. Note text ≤ 2000 chars as now. Points closer than 1px are dropped while drawing.
- Convex arrays hold at most 8,192 items and documents at most 1 MiB. Flat `pts` arrays at 2,000 points are 4,000 numbers.
- The validator keeps accepting `highlight` marks. Box highlights keep rendering and their cards keep the "Highlight" label.
- Copy: tool label "Marker". Inks "Pen" and "Highlighter". Composer title "Add a drawing", field "Note (optional)", post button "Post drawing". Card tag "Drawing". Stat "Drawings" (counts `drawing` and `highlight`). Badges "Moved" and "Drawn on a wider screen" / "Drawn on a narrower screen". Discard dialog title "Discard this drawing?".
- `localStorage` access (the remembered ink) is wrapped in try/catch.
- Existing behavior holds: Esc backs out one step, page links and buttons don't fire while a tool is active, nothing is placed mid-glide, reduced motion, owner and device rules.

## Review Focus

1. **A click or tap with no movement while Marker is on:** nothing is drawn, no composer opens, and the page's link under it doesn't fire. Test: Task 5 `a click without moving draws nothing`.
2. **Posting a drawing fails (offline or rate limit):** every stroke and the typed note stay, an error shows, and Post works again with the same clientId (one mark, not two). Test: Task 5 `failed post keeps the strokes and retries once`.
3. **Someone else's mark arrives mid-drawing:** the draft's strokes and the open composer are untouched. Test: Task 5 `a live mark arriving keeps the draft`.
4. **A stroke dragged off the page into the sidebar or past the window edge:** it ends cleanly when released and is kept. A press that *starts* on comment mode's own interface draws nothing. Test: Task 5 `dragging into the sidebar still ends the stroke`.
5. **Drawing over the typed headline** (`#slot` rewrites its letters): the stroke anchors to the stable headline, not a letter that vanishes. Test: Task 3 `a stroke over the typed headline survives retyping`.

### Task 2: Stroke geometry (`review/ink.js`)

**Files:**
- Create: `review/ink.js`
- Test: `tests/unit/ink.test.js`

**Interfaces:**
- Produces:
  - `INK`: `{ pen: { color: '#D93A22', width: 2.6, phoneWidth: 4 }, highlighter: { color: 'rgba(255, 205, 40, .5)', width: 16, phoneWidth: 24 } }`
  - `inkWidth(ink: 'pen'|'highlighter', viewportWidth = innerWidth): number`: `phoneWidth` at ≤759.
  - `simplify(points: number[][], minDist = 1): number[][]`: drops points closer than `minDist` to the last kept point, and always keeps the last point.
  - `bounds(points: number[][]): { x, y, w, h }`
  - `toFlat(points: number[][], origin: {x, y}): number[]`: offsets rounded to 0.5.
  - `fromFlat(flat: number[], origin: {x, y}, scale = 1): number[][]`
  - `centerline(points: number[][]): string`: smoothed SVG `d` (quadratic curves through midpoints, as in the mockup).
  - `penOutline(points: number[][], { width: number, pressures?: number[] }): string`: a closed, filled SVG `d` ending in `Z`.
  - `isAlongText(points: number[][]): boolean`: true when the bounding box is at least 24px wide, its height is ≤ max(40, 0.35 × width), and the stroke doesn't double back (end x minus start x covers at least 60% of the width).
  - `sketchSvg(strokes: Stroke[], { w = 96, h = 56 } = {}): string`: an `<svg viewBox>` with every stroke placed at `origin + pts`, scaled to fit with 4px padding. The pen is drawn as `penOutline` and the highlighter as a `centerline` stroke, both in the ink colors.

- [ ] **Step 1: Write the failing tests** in `tests/unit/ink.test.js` (node environment):
  - `simplify drops points under 1px apart and keeps the last`: `[[0,0],[0.4,0],[2,0],[2.3,0]]` → `[[0,0],[2,0],[2.3,0]]`.
  - `toFlat and fromFlat round-trip at scale 1 and double at scale 2`.
  - `toFlat rounds to halves`: 1.26 → 1.5.
  - `penOutline is closed and thinner at the ends than the middle`: for a 40-point straight line with `width: 4`, `d` ends with `Z`. The outline's distance from the centerline is less than 1.2 at points 0 and 39, and more than 1.6 at point 20 (parse the `d` numbers).
  - `penOutline uses pressure when given`: pressures all 1 give a wider middle than pressures all 0.2.
  - `isAlongText: an underline yes, a circle no, a back-and-forth scribble no`.
  - `inkWidth is wider at 390 than at 1440` for both inks.
  - `sketchSvg fits two strokes far apart into the box`: every coordinate in the output's paths falls within 0–96 × 0–56.
- [ ] **Step 2: Run** `npx vitest run tests/unit/ink.test.js`. Expected: FAIL (module missing).
- [ ] **Step 3: Implement `review/ink.js`.** `penOutline` algorithm:
  - Per point, width = `width × taper × factor`.
    - `taper = 0.35 + 0.65 × min(1, i/6, (n−1−i)/6)`.
    - `factor = 0.4 + 0.9 × pressure` when pressures are given. Otherwise `clamp(1.15 − segLen/30, 0.55, 1.15)`, where `segLen` is the distance to the previous point.
  - The normal comes from the tangent `p[i+1] − p[i−1]`. Left side points = p + n·w/2, right side = p − n·w/2.
  - The path runs forward along the left side, takes a round cap (SVG arc) to the right side, runs back along the right side, takes a round cap, then `Z`.
  - A 1-point stroke returns a small circle.

- [ ] **Step 3: Implement.**
  - `anchorStroke`:
    - Simplify the points.
    - Choose a probe point. For a loop (not `isAlongText`), use the bounding box's center. For a flat stroke, use the box's horizontal center at 6, 14, then 24px above its top, taking the first that hits text.

    - For pen strokes with both box sides ≥ 16px, store `inside` = up to 4 `anchorAt` points inside the box: the center, plus the points ¼ and ¾ along the long axis on the middle line, skipping any that land on the same element.

  - `resolveStroke`:
    - The origin comes from `char` (the character rect's top-left plus scroll) when it resolves, else from `resolveAnchor(at)`.
    - `scale = clamp(sizeNow / size, 0.25, 4)`.
    - `points = fromFlat(pts, origin, scale)`.
    - `bands` only for `text`: build a `Range` from start to end and group `getClientRects()` by line (tops within 2px). Each band is `{ x1, x2, y: line middle, h: 0.75 × line height }` in page coords. If either end won't resolve, `bands` is `null` and the stroke draws as drawn.
